# 0009. The code rules are enforced by the build, with the .NET SDK analyzers and plain tests

- Status: Accepted
- Date: 2026-11-11

## Context

Version 1.1.0 is written by coding agents under the maintainer's review
([ADR 0007](0007-redesign-on-a-development-branch.md)). A rule that only a document states is broken sooner or
later; a rule that the build checks is not. The rules must exist before the first project does.

## Decision

Every rule that a tool can check fails the build or a test; none has an allow-list.

- `Directory.Build.props`: nullable reference types, warnings as errors, code style enforced in the build,
  `AnalysisLevel` `latest-recommended`, no implicit usings, no transitive project references, package lock
  files. NuGet audit warnings stay warnings, so that a later advisory does not break an unchanged commit; CI
  fails on them separately.
- `Directory.Packages.props`: central package management with transitive pinning.
- `.editorconfig`: the style rules at `warning`, and three rules silent by default: naming (IDE1006),
  `sealed` on internal types (CA1852) and unused usings (IDE0005).
- One list of banned symbols, read by `Microsoft.CodeAnalysis.BannedApiAnalyzers`: the clock is `TimeProvider`,
  and Win32 declarations are generated by CsWin32, not written by hand.
- Architecture tests in plain reflection and project-file reading: allowed project references, no catch-all
  names, no static mutable state. Each rule is also tested on a fixture that breaks it.
- `global.json` pins the SDK feature band; `web/package.json` pins the Node.js line.

References: Microsoft Learn
([code analysis](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/overview),
[naming rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/naming-rules),
[CA1852](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca1852),
[auditing packages](https://learn.microsoft.com/nuget/concepts/auditing-packages),
[central package management](https://learn.microsoft.com/nuget/consume-packages/central-package-management));
the banned-symbol lists of `dotnet/roslyn`, `microsoft/testfx`, `dotnet/orleans` and `jellyfin/jellyfin`; the
reflection tests of `dotnet/efcore`; the build files of `dotnet/eShop`, `microsoft/aspire` and
`git-ecosystem/git-credential-manager`.

## Rejected alternatives

- The same rules with the defaults as they are: naming, `sealed`, the clock and interop would stay with
  review.
- Maximum strictness, with Meziantou.Analyzer, Roslynator, SonarAnalyzer and ArchUnitNET: overlapping and
  conflicting rules, a slower build, and for SonarAnalyzer a source-available licence, not an open-source
  one. NetArchTest.Rules has had no release since 1.3.2 (2021); ArchUnitNET reads IL, and until
  [issue 498](https://github.com/TNG/ArchUnitNET/issues/498), closed on 2026-10-09, its negative rules passed
  in Release builds.

## Consequences

- A warning stops the build on every machine. A new SDK feature band brings new analyzer rules, so it arrives
  by a commit that edits `global.json`.
- A rule that no analyzer covers needs a test, or stays with review.
- The table of allowed project references starts empty: the host architecture fills it.
